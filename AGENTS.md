# Project Engineering Rules

- Read `CONSTITUTION.md`, `HANDOFF.md`, and the current approved ticket before modifying code.
- Keep changes within the approved scope. Report unexpected changes rather than expanding scope.
- Use the project's real verification commands; never claim success based on assumptions.
- Do not access production systems, secrets, or external services without explicit approval.
- Do not commit, push, merge, deploy, or run destructive commands without explicit human approval.
- Prefer readable and maintainable code. Preserve security, validation, and error handling.
- Communicate with the user in Persian. Write source code, code comments, and command names in English.
- Use optional MCP tools only when necessary. Keep full verification logs outside chat when safe.
- Antigravity skills and external tracker configuration are helpers; Git, test output, and reviewed artifacts are the evidence.
