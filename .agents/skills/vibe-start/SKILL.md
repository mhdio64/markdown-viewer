# آغاز یا ادامه طراحی پروژه

۱. `AGENTS.md`، `PRD.md`، `SPEC.md`، `CONSTITUTION.md` و `HANDOFF.md` را بررسی کن؛ فقط بخش‌های مرتبط را بخوان.
۲. اگر ایده خام است، با `grill-with-docs` و پرسش‌های چالشی مسئله، کاربران، ریسک‌ها، حد MVP و نیازهای غیرعملکردی را روشن کن. کدنویسی نکن.
۳. با `to-spec`، پیش‌نویس Spec را آماده کن و برای تأیید ارائه بده؛ سپس در صورت نیاز UI با Stitch را طراحی کن.
۴. فقط پس از تأیید Spec با `to-tickets` برش‌های کوچک و قابل تست بساز. Issue Tracker پیکربندی‌شده را بررسی کن.
۵. معماری و تصمیمات مهم را با ADR مستند کن؛ از کپی‌کردن متن کامل گفتگو در اسناد پرهیز کن.
۶. پیش از شروع پیاده‌سازی متوقف شو و نقشه تیکت‌ها را برای تأیید ارائه بده.
